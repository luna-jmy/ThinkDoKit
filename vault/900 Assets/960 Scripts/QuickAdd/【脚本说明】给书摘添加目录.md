# QuickAdd标题格式化脚本使用说明

简介：根据有书籍目录的笔记把书摘里的目录标上层级

## 📋 脚本功能

这个QuickAdd宏脚本可以：

1. 从指定的目录(TOC)笔记中读取内容
2. 将当前笔记中匹配的文本自动转换为相应级别的标题
3. 根据目录中的缩进层级自动设置标题级别（## → ### → #### 等）
4. 自动删除转换后的重复标题，保持笔记结构清晰

## 🚀 快速开始

### 1. 安装QuickAdd插件

- 在Obsidian中安装并启用QuickAdd插件
- 创建新的宏(Macro)，选择"User Script"类型
- 将脚本代码粘贴到编辑器中

### 2. 准备目录文件

创建一个目录笔记，格式如下：

```markdown
### **目录**
介绍
  方法论
    数据收集
    数据分析
  结果
    主要发现
    次要发现
结论
参考文献
```

### 3. 准备待处理的笔记

确保你的笔记中包含与目录相匹配的文本：

```markdown
介绍
这是介绍部分的内容...

方法论
这是方法论部分...

数据收集
具体的数据收集过程...

结论
最终的结论...
```

### 4. 运行脚本

- 打开待处理的笔记
- 运行QuickAdd宏
- 在弹出的输入框中输入目录文件名（如：`TOC.md`）
- 脚本会自动处理并格式化标题

## 📝 使用步骤详解

### 步骤1：设置目录文件

目录文件必须包含特定的标识符：`### **目录**`

支持的目录格式：

- **无缩进**：转换为 `## 标题` (2级标题)
- **1级缩进**：转换为 `### 标题` (3级标题)
- **2级缩进**：转换为 `#### 标题` (4级标题)
- **以此类推**：最多支持6级标题

### 步骤2：文件名输入

脚本支持多种文件名格式：

- `TOC.md` - 完整文件名
- `TOC` - 不带扩展名（会自动添加.md）
- `目录.md` - 中文文件名
- `我的目录` - 中文文件名不带扩展名

### 步骤3：自动处理

脚本会：

1. 查找并读取目录文件
2. 提取目录内容
3. 在当前笔记中查找匹配的文本
4. 按缩进级别转换为相应的标题
5. 删除重复的标题
6. 保存修改后的文件

## ⚙️ 配置选项

### 基础标题级别

```javascript
const baseHeadingLevel = 2;
```

- 设置起始标题级别，默认为2（即`##`）
- 可以修改为1-6之间的任何数字

### 目录标识符

```javascript
const tocIdentifier = "### **目录**";
```

- 设置目录文件中的标识符
- 可以修改为任何你喜欢的格式

## 🔧 注意事项

### 文件要求

1. **目录文件必须存在**：确保输入的文件名对应的文件存在于vault中
2. **目录标识符必须匹配**：文件中必须包含`### **目录**`这行
3. **当前文件必须打开**：运行脚本前确保目标笔记已打开

### 文本匹配规则

1. **精确匹配**：目录中的文本必须与笔记中的文本完全一致
2. **整行匹配**：只匹配独立的行，不会匹配行内的部分文本
3. **大小写敏感**：`Introduction`和`introduction`会被视为不同的文本

### 缩进处理

1. **支持空格和制表符**：脚本会自动检测缩进类型
2. **缩进计算**：默认2个空格=1级缩进，1个制表符=1级缩进
3. **最大标题级别**：限制为6级标题（`######`）

### 重复处理

1. **基于文本内容**：比较标题的文本内容，忽略标题级别
2. **保留首次出现**：删除后续重复的标题
3. **例如**：`## 介绍`和`### 介绍`会被视为重复

## 🐛 故障排除

### 常见错误

**错误：文件未找到**

- 检查文件名是否正确
- 确认文件是否存在于vault中
- 尝试使用完整文件名（包含.md扩展名）

**错误：目录标识符未找到**

- 检查目录文件中是否包含`### **目录**`
- 确认标识符的格式完全一致（包括空格和符号）

**错误：没有匹配的内容**

- 检查目录中的文本是否与笔记中的文本完全一致
- 确认目录文本没有多余的空格或符号
- 检查是否存在不可见字符

### 调试方法

1. **打开开发者控制台**：按`Ctrl+Shift+I`（Windows/Linux）或`Cmd+Option+I`（Mac）
2. **查看控制台输出**：脚本会输出详细的调试信息
3. **检查文件列表**：控制台会显示所有可用的文件名

### 调试信息说明

- `✓ Replaced: "xxx" with "## xxx"`：成功转换的标题
- `✗ No match found for: "xxx"`：未找到匹配的文本
- `✓ Keeping heading: "## xxx"`：保留的标题
- `✗ Removed duplicate heading: "### xxx"`：删除的重复标题

## 🎯 最佳实践

### 1. 标准化目录格式

- 使用一致的缩进（建议2个空格）
- 避免使用特殊字符和标点符号
- 保持目录条目简洁明了

### 2. 文件命名规范

- 使用描述性的文件名
- 避免使用特殊字符
- 建议使用英文文件名以提高兼容性

### 3. 笔记结构优化

- 确保待处理的文本位于独立的行
- 避免在目录文本中使用标点符号
- 保持文本的一致性

### 4. 版本控制

- 在运行脚本前备份重要文件
- 使用Git等版本控制系统跟踪变更
- 定期检查处理结果的准确性
